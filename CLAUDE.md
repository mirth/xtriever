# Xtriever — Agent Guidance

Xtriever is a cross-platform hybrid retrieval engine for RAG: BM25 → dense → fusion → re-rank → LTR.

**`.specify/memory/constitution.md` (v1.4.0) is the highest authority in this repository.** It
supersedes this file, the templates, and the README. Read it before planning or implementing
anything. If this file and the constitution ever disagree, the constitution wins and this file is
the bug — fix it rather than following it.

Principles are referenced here by number (I–VII) so this file cannot drift from their wording.
Plans enumerate all seven plus the Agent Operating Rules as PASS/FAIL gates; that table lives in
`.specify/templates/overrides/plan-template.md` and is filled in by `/speckit-plan`.

## Agent Operating Rules

Quoted verbatim from the constitution's "Agent Operating Rules". These apply *in addition to*
Principles I–VII, not instead of them.

1. Never invent an API. If unsure how a crate works, read the docs for the pinned version
   (`cargo doc --open`, docs.rs) and cite the item in the plan.
2. Do not modify `xtriever-core` traits or `deny.toml` unless the spec says so; otherwise stop and ask.
3. Work one spec at a time on its branch; keep PRs under ~800 changed lines — split otherwise.
4. Write the acceptance tests first and commit them failing.
5. Before declaring a task done, run the full gate locally and paste eval/bench deltas into the PR.
6. If a metric drops or a target fails to build, stop and report. Never "fix" it by weakening
   tests, tolerances or thresholds.
7. Prefer boring code: no macros for their own sake, no trait gymnastics, no premature generics.

## The local gate (Rule 5)

Run all of these before calling anything done. Never weaken them to get a pass (Rule 6).

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets    # RUSTFLAGS="-D warnings" in CI; warnings are errors
cargo nextest run --workspace
cargo deny check
cargo check --workspace --target aarch64-apple-ios
cargo check --workspace --target aarch64-apple-ios-sim
cargo check --workspace --target aarch64-linux-android
cargo check --workspace --target wasm32-unknown-unknown   # best-effort, may fail (tracked)
python3 reference/gen_026_fixtures.py && python3 reference/gen_026_fixtures.py --check-oracle   # Feature 026: dense goldens and oracle from reference/, exit 1 on any difference
(cd python && .venv/bin/maturin build) && uv pip install --force-reinstall target/wheels/xtriever-*.whl \
  && python/.venv/bin/pytest python/tests -q                # Feature 011: the Python surface, models present (CI runs only `-m "not models"`)
scripts/check-demos.sh                                      # every demo built against the engine as it stands: the Python demos' tests, the iOS and Android demos compiled with their tests (no device)
```

A change to any binding-visible record (`xtriever-ffi` types) must pass `scripts/check-demos.sh`:
the demos construct some of those records themselves, and a new field compiles in every library
while breaking a demo (Feature 027's `StageReport.sparseSkipped` broke the Android demo that way).

Ranking-affecting changes to `lexical` / `dense` / `rerank` / `ltr` / `pipeline` additionally need
`xtriever-eval` on SciFact / NFCorpus / FiQA, with nDCG@10 and Recall@100 deltas in the PR
description, plus `criterion` results inside the spec's budget (Principles II and IV). The blocking
set is the constitution's "Quality Gates (CI)" table.

## Hard constraints worth having in front of you

These are the rules most easily broken by accident. They are enforcements of the principles, not
additions to them — see the constitution for the full text and rationale.

- **Pure crates stay pure (III).** `xtriever-core`, `-analysis`, `-pipeline`, `-ltr`, `-eval` are
  `std`-only: no C/C++ build deps, no `async`, no `tokio`, no unconditional threads, no
  `std::time::Instant` in library code (it does not exist on wasm32). C/C++ deps belong only in
  `xtriever-dense`, `-rerank`, `-ffi`, behind non-default Cargo features, enforced by `deny.toml`.
- **Tests come before code (II).** Commit them failing. Behaviour with a reference implementation
  (BM25 scoring, tokenization, embeddings, GBDT prediction) is verified against golden fixtures
  generated by `reference/` (Python), at tolerances the spec states.
- **The contract needs an ADR (V).** Changing an `xtriever-core` trait, an on-disk format, or error
  semantics requires human review and an ADR in `docs/adr/`. So does building a commodity component
  by hand (I) or landing a ranking regression (II).
- **Dependencies point downward (V).** `core` ← stage crates ← `pipeline` ← `ffi`/`cli`. One crate
  per stage. Internal `DocId` is a dense `u32`; backends never see external string ids.
- **Degrade, don't error (VI).** A failed or timed-out ML stage falls back to the previous stage's
  results unless the caller opted into strict mode. Identical index + query + config must give
  identical results, ties broken by ascending `DocId`.
- **No `unwrap` / `expect` / `panic!` / `todo!` in library code (VII).** The workspace lints in
  `Cargo.toml` deny them. Library errors are `thiserror` enums; `anyhow` is for binaries only.
  Hand-written `unsafe` is confined to `xtriever-dense` and `xtriever-rerank`, and there to SIMD
  kernels and read-only memory mapping behind a non-default feature
  ([ADR-0007](docs/adr/0007-unsafe-readonly-mmap-in-dense.md),
  [ADR-0009](docs/adr/0009-unsafe-readonly-mmap-in-rerank.md));
  each block preceded by `// SAFETY:` and tested against the safe path. `xtriever-ffi` additionally
  carries a crate-level `#![allow(unsafe_code)]` for uniffi's generated FFI scaffolding; modules
  with hand-written logic re-declare `#![deny(unsafe_code)]` (constitution v1.3.0,
  [ADR-0003](docs/adr/0003-uniffi-scaffolding-requires-unsafe-allow.md)).
- **Add dependencies with `cargo add` (VII).** Never write a version number from memory. Edition
  2024, toolchain pinned in `rust-toolchain.toml`, `Cargo.lock` committed.

## Workflow

Features go through Spec Kit: `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` →
`/speckit-tasks` → `/speckit-implement`. Amending the constitution means a PR touching
`.specify/memory/constitution.md` plus an ADR, human approval, and a version bump (MAJOR: principle
removed or redefined; MINOR: principle added or expanded; PATCH: wording).
