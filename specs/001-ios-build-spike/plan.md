# Implementation Plan: iOS Build Spike — tantivy, tokenizers, candle on Device

**Branch**: `001-ios-build-spike` | **Date**: 2026-09-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-ios-build-spike/spec.md`

**Note**: This template is filled in by the `/speckit-plan` command; its definition describes the execution workflow.

## Summary

Prove that tantivy, tokenizers and candle build for the two iOS triples, reach Swift through a
uniffi binding in `xtriever-ffi`, and run on a physical iPhone — indexing 1,000 documents, running
one BM25 query, and embedding one sentence with all-MiniLM-L6-v2 — then record installed size, peak
memory footprint and per-operation wall time, with every failure preserved as a finding.

Phase 0 ([research.md](./research.md)) resolved the dependency question by measurement and found one
blocking defect: **candle-core 0.10 and later cannot be used here.** It hard-codes a `tokenizers` feature
that pulls `onig_sys` (C, banned by `deny.toml`), and 0.11.0 additionally fails to compile on stable
Rust 1.91.1 for the host and simulator targets because it needs the nightly-only
`stdarch_neon_f16`. candle **0.9.2** has neither defect and passes `cargo check` on host, device and
simulator with zero C compilation anywhere in the graph. Pinning below the current version is a
deliberate Principle VII deviation, accepted in [ADR-0001](../../docs/adr/0001-pin-candle-0-9-2.md)
on 2026-09-10; with that and ADR-0002 accepted, the Constitution Check now passes on all 14 rows.

Two further Phase 0 findings shape the design rather than blocking it: tantivy's multi-threaded
writer does not allocate `DocId`s reproducibly (so the writer is fixed to one thread, or FR-014's
exact-equality oracle would be flaky for reasons unrelated to iOS), and the model's `tokenizer.json`
bakes in truncation/padding at 128 tokens while the reference behaviour is 256 (so Rust and Python
would disagree before iOS entered the picture).

## Technical Context

**Language/Version**: Rust 1.91.1 (pinned in `rust-toolchain.toml`), edition 2024, `resolver = "3"`. Swift for the measurement harness.

**Primary Dependencies**: `tantivy 0.26.2` (`default-features = false`, features `mmap`, `stopwords`, `lz4-compression`, `stemmer`); `tokenizers 0.23.2` (`default-features = false`, features `fancy-regex`); `candle-core`/`candle-nn`/`candle-transformers` **0.9.2** (default features, i.e. `default = []`); `uniffi 0.32.1`. All measured C-free — see [research.md](./research.md) D1–D4.

**Storage**: tantivy `MmapDirectory` index written into the iOS application sandbox; bundled model weights read from the app bundle.

**Testing**: `cargo nextest` for host tests; committed golden fixtures generated by a Python script in `reference/`; an XCTest-hosted Swift harness for the on-device run. No `criterion` — this spike sets no budgets (FR-023).

**Target Platform**: host `aarch64-apple-darwin`, `aarch64-apple-ios` (device), `aarch64-apple-ios-sim`. `wasm32-unknown-unknown` fails at `getrandom` and is out of scope (FR-030, research D13). Android untested (FR-030).

**Project Type**: library + FFI leaf crate + a throwaway Swift measurement app.

**Performance Goals**: none. The spike establishes the baseline that later specs set budgets against (FR-023, SC-006).

**Constraints**: peak `phys_footprint` ≤ 300 MB (Principle III default, FR-020) — of which 87.1 MiB is bundled fp32 weights before anything runs; no C/C++ build dependency reachable from the five pure crates; no `std::time::Instant`, `async`, `tokio` or unconditional threads introduced into the pure crates (FR-010); `xtriever-core` traits and `deny.toml` unchanged (FR-009, Rule 2).

**Scale/Scope**: 1,000 short documents, 1 query, 1 sentence. One physical iPhone. 1,000 documents is **1%** of the 100,000-chunk configuration the 300 MB ceiling is written against (FR-021).

### Source Code (repository root)

Only `xtriever-ffi` gains Rust code. The five pure crates and the other stage crates are untouched,
which is what keeps Principle III's row green.

```text
crates/
├── xtriever-core/       # UNTOUCHED — traits, DocId, errors; #![forbid(unsafe_code)]
├── xtriever-analysis/   # UNTOUCHED
├── xtriever-lexical/    # UNTOUCHED — deliberately: spike code does not squat in it (see Complexity)
├── xtriever-dense/      # UNTOUCHED — same
├── xtriever-rerank/     # UNTOUCHED
├── xtriever-ltr/        # UNTOUCHED
├── xtriever-pipeline/   # UNTOUCHED
├── xtriever-eval/       # UNTOUCHED
├── xtriever-cli/        # UNTOUCHED
└── xtriever-ffi/        # ALL spike Rust, behind a non-default `spike` feature
    ├── Cargo.toml       #   crate-type = ["cdylib", "staticlib"]; [[bin]] uniffi-bindgen
    ├── src/lib.rs       #   uniffi::setup_scaffolding!(); the three #[uniffi::export] fns
    ├── src/spike/       #   index/query/embed implementations + the typed error enum
    └── src/bin/uniffi-bindgen.rs   # fn main() { uniffi::uniffi_bindgen_swift() }

reference/
├── fixtures/            # committed goldens: corpus, expected ranking, tokens, embedding
└── gen_001_fixtures.py  # the generator (Principle II: goldens come from reference/)

harness/ios/             # throwaway-by-design Swift app; DURABLE per FR-031
├── XtrieverSpike/       #   3 buttons, 3 measurements, results exportable as JSON
└── Measure.swift        #   phys_footprint / ri_lifetime_max_phys_footprint / CLOCK_UPTIME_RAW

docs/adr/
├── 0001-pin-candle-0-9-2.md                      # BLOCKS Principle VII
└── 0002-unsafe-mmap-safetensors-measurement.md   # BLOCKS Principle VII
```

**Structure Decision**: all spike Rust is concentrated in `xtriever-ffi`, the leaf crate the spec
already names, behind a non-default `spike` feature. The stage crates stay empty placeholders so that
throwaway code does not have to be deleted or worked around when the lexical and dense specs land.
Dependencies still point strictly downward — `xtriever-ffi` → `tantivy`/`candle`/`tokenizers` — and
the deviation is that it skips `pipeline` and the stage crates, which currently contain nothing to
route through. The Swift harness lives outside `crates/` because it is not a Rust crate and must not
enter the workspace build.
