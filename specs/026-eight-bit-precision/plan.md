# Implementation Plan: Eight-Bit Precision End to End

**Branch**: `026-eight-bit-precision` | **Date**: 2026-09-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/026-eight-bit-precision/spec.md`

## Summary

Two halves, two pull requests, one artefact rebuild.

**PR A — the vectors.** Dense format version 3: each row becomes an identifier, a norm, a scale
and one signed byte per dimension, 396 bytes against today's 1,544 at dimension 384. Scoring is
an integer dot product dequantised once per row. No float vectors are kept and no rescoring pass
exists (spec FR-003, the owner's decision), so the ranking moves for a small minority of hits —
0.0006 nDCG@10 on both datasets the study measured, an eighth of the threshold this feature
holds itself to.

**PR B — the models.** Both stages learn to load an eight-bit GGUF artefact beside the
as-published float weights, with the manifest deciding which an installation uses (FR-012). The
weights come from the owner: `all-MiniLM-L6-v2.Q8_0.gguf` and `ms-marco-MiniLM-L-6-v2-q8_0.gguf`,
pinned by repository, revision and checksum like every other model. Each fingerprint names the
artefact it was loaded from, so an index records which weights produced it.

Both halves invalidate every artefact — the format changes, and a different embedder means a
different index — which is why they are one feature: the Wikipedia corpus is embedded once at
the end rather than twice.

**Language/Version**: Rust, workspace edition 2024, toolchain pinned. No new language surface.

**Primary Dependencies**: `candle-core 0.9.2`, already pinned by
[ADR-0001](../../docs/adr/0001-pin-candle-0-9-2.md) and already carrying everything the model
half needs: `quantized::gguf_file::Content::read` for the file, `quantized::QTensor` with
`dequantize` for the tensors that are not matrix multiplies, and `quantized::QMatMul`
(`from_qtensor`, and `Module::forward`) for the ones that are. `candle-transformers 0.9.2` has
twenty-two quantized models and **no quantized BERT**, so the forward pass is ours to write —
which it already is in both crates. No dependency is added; `cargo add` is not needed.

**Storage**: dense format version 3, one file per generation as today. Rows shrink from
`id u32 · norm f32 · vector dim×f32` to `id u32 · norm f32 · scale f32 · codes dim×i8`. Version
1 and version 2 files are refused by name with the rebuild instruction, exactly as version 1 is
refused now.

**Testing**: `cargo nextest` for the crates, the oracle fixtures regenerated by `reference/`, and
`xtriever-eval` on SciFact, NFCorpus and FiQA for the quality gate. The three studies already in
`reference/` (`int8_vectors_study.py`, `int8_model_study.py`, `int8_reranker_study.py`) are the
evidence that justified the attempt; the gate is the harness on the real artefacts.

**Target Platform**: host plus `aarch64-apple-ios`, `aarch64-apple-ios-sim`,
`aarch64-linux-android`, as the constitution requires. Nothing here is platform-specific.

**Project Type**: two stage crates (`xtriever-dense`, `xtriever-rerank`), their fixtures, the
model manifests and the fetch script. No new crate.

**Performance Goals**: none are budgeted for latency, because the owner waived the kernel speed
probe. The budgeted numbers are size: the dense file under a third of today's, both artefacts
together under 60 MB, and the shipped corpus's peak resident size under the project's 600 MB
ceiling. A scan benchmark is still recorded for the change, as Principle IV requires of a change
to a hot path.

**Constraints**: quality within 0.005 of every committed baseline on both metrics and all three
datasets (FR-009), determinism unchanged (same index, query and configuration give the same
answer), the tokenizer still comes from the pinned float model directory because neither GGUF
repository ships one, and no continuous-integration job gains a dataset or a model.

**Scale/Scope**: 427,947 vectors in the shipped corpus, 22.7 M parameters per model, two crates
touched, and one full corpus re-embedding at the end of the feature.

neither eight-bit repository ships one — the artefact supplies weights only.
