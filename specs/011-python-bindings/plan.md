# Implementation Plan: Python Interface and Bindings

**Branch**: `011-python-bindings` | **Date**: 2026-09-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/011-python-bindings/spec.md`

## Summary

A `pip`-installable `xtriever` package whose module is generated by uniffi from the same
exports the Swift bindings come from, built into a per-platform wheel by maturin's `uniffi`
mode through the crate's own `uniffi-bindgen` bin; verified against the 007 goldens (already
16 / 16 bit-identical in the research run) with one exception class per engine error kind
and the interpreter lock released during engine calls. Plus the one addition the spec asks
for (Q1 = B): the builder on the wire — schema, documents, `create` / `add` / `add_embedded`
/ `delete` / `commit` / `merge` / `contains` on the existing `IndexHandle` — so a Python
program goes from its documents to a search. One Linux CI job, model-free. Nothing in the
engine, the Swift package or the app changes.

## Technical Context

**Language/Version**: Rust 1.91.1 (edition 2024) for the FFI additions; Python ≥ 3.9 for the
package (tested 3.12, 3.13 on macOS arm64; 3.12 on Linux in CI).

**Primary Dependencies**: `uniffi 0.32.1` (existing; `uniffi::uniffi_bindgen_main` behind the
existing `cli` feature — research D1/D2); maturin 1.15 (build backend, Python side only);
pytest; `uv` for environments. No new Rust dependency.

**Storage**: none new; indexes are the pipeline's (format version 2, unchanged).

**Testing**: FFI `tests/build.rs` (model-backed, `#[ignore]`, release); Python `pytest`
(`models` marker for the model-backed tests; the model-free subset in CI); the existing FFI
parity suite and the Swift suite unchanged.

**Target Platform**: macOS arm64 and Linux x86_64 wheels (`py3-none-<platform>`); the Rust
gate's cross-target checks unchanged.

**Project Type**: library (FFI additions) + Python package + CI job.

**Performance Goals**: binding overhead ≤ 5 % of the engine's `elapsed_ms` (SC-004); the
interpreter lock released (SC-005); the CI job under 10 minutes (SC-006).

**Constraints**: no `unsafe` (the FFI's hand-written modules re-declare `#![deny]`), no engine
change, no models/datasets/simulators in CI, no generated code or shared library committed,
no device or team identifiers anywhere.

**Scale/Scope**: FFI: ~180 lines of wire types + conversions, ~80 of exports, ~220 of tests;
Python: ~40 of package, ~380 of tests, ~60 of config/README; CI ~45. ≈ 1,000 lines → **two
PRs** (Rule 3): PR A = the package over the existing surface (no FFI change but the bindgen
dispatch), its suite, the wheel, CI; PR B = the builder exports and their suites.
