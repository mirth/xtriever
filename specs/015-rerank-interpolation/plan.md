# Implementation Plan: Interpolated Re-ranking as the Default

**Branch**: `015-rerank-interpolation` | **Date**: 2026-09-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/015-rerank-interpolation/spec.md`

## Summary

The pipeline's re-rank stage gains a second order rule — the head ordered by
`(1 − α)·minmax(fused) + α·minmax(cross-encoder)`, α 0.5, ties by fused rank — as the default,
with the replace-order rule kept bit-identical under a named mode. The mode is recorded in
the descriptor (`rerank_mode`, missing = the default, format version unchanged; ADR-0012),
overridable per search, reported in info and explain (`rerank_combined`, feature
`rerank.combined`), and exposed through the FFI and Python as `Option<RerankMode>` with
`None` = default. Oracles: the 006 reference generator extended with the interpolation rule
(golden cases), and 014's `lin-0.5-d20` cells, which `hybrid-rerank-v3` must reproduce per
query to 1e-6. The 007 parity goldens are regenerated by their generator; every earlier
baseline stays byte-identical.

## Technical Context

**Language/Version**: Rust 1.91.1 (edition 2024); Python 3.12 for the 006 generator (`reference/.venv-004` or `.venv-012`, stdlib only for the rule) and the per-query comparison

**Primary Dependencies**: unchanged — `serde` (descriptor enum), `uniffi 0.32.1` (the wire enum, `default = None`), the pinned re-ranker and embedder for the runs and goldens; no `cargo add`

**Storage**: the descriptor gains one key (`rerank_mode`), format version 2 unchanged; baselines under `specs/015-rerank-interpolation/baselines/`; regenerated `swift/Xtriever/Tests/Fixtures/expected.json` and `reference/fixtures/006/pipeline_order.json` (+ `interpolate_cases`)

**Testing**: `cargo nextest` (pipeline golden + property tests, descriptor round trip, FFI surface), `pytest` (Python surface, parity goldens), the Swift suite on the simulator (owner, local), `xtriever-eval` on the three sets verified by the 003 scorer and compared per query with 014's cells

**Target Platform**: host + `aarch64-apple-ios`, `aarch64-apple-ios-sim`, `aarch64-linux-android` (wasm32 best-effort) — the pipeline stays `std`-only

**Project Type**: library (pipeline) + ffi + eval + docs

**Performance Goals**: no new claim; cross-encoder calls per query unchanged (depth 20); the extra work is O(depth) arithmetic

**Constraints**: no `xtriever-core` trait or `deny.toml` change; no new dependency; α ∈ [0, 1] validated, never clamped; determinism (ties by fused rank → `DocId`); an ADR for the default and the descriptor key

**Scale/Scope**: pipeline ~150 lines, ffi ~70, eval ~50 + example ~20, reference generator ~60, tests ~250, docs/ADR; regenerated goldens and three baselines excluded from the ~800 budget (spec SC-006)

**Structure Decision**: the rule lives in the pipeline (the only crate that orders re-ranked
hits); the eval crate mirrors the mode with its own enum (it depends on `core` only); the FFI
maps between its wire enum and the pipeline's. Dependency direction unchanged: `core` ←
stage crates ← `pipeline` ← `ffi` / `cli`, `eval` beside them.
