# Research: Interpolated Re-ranking as the Default

**Feature**: `015-rerank-interpolation` | **Date**: 2026-09-16 | **Plan**: [plan.md](./plan.md)

## D1 — The rule, and where it lives

The pipeline's order rule is one public function, `xtriever_pipeline::order_reranked(fused:
&[(DocId, f64)], scores: &[Option<f32>], k) -> Vec<(DocId, f64, Option<f32>)>`
(`crates/xtriever-pipeline/src/rerank.rs:13–35`), called once from `HybridIndex::rerank`
(`src/search.rs:308–315`) after the re-ranker's scores are validated finite and of the right
length. **Decision**: add `RerankMode { Replace, Interpolate { alpha: f64 } }` to the
pipeline's public types and a second function `order_interpolated(fused, scores, k, alpha)
-> Vec<(DocId, f64, Option<f32>, Option<f64>)>` (the fourth element the combined score),
plus `order_head(mode, fused, scores, k)` dispatching between the two; `order_reranked` is
untouched (the 006 goldens and property tests keep passing unchanged, spec FR-002). The rule
reproduces 014's derivation operation for operation (`reference/rerank_study.py`
`minmax` / `order_lin`): over the scored head, `f = minmax(fused as f64)`, `c = minmax(s_c as
f64)` with `minmax(v) = (v − lo) / (hi − lo)` and all zeros when `hi == lo` (one candidate or a
constant column), `s = (1 − α)·f + α·c` in f64 in that order (no FMA — Rust does not fuse by
default), sort by `(−s, fused rank)`; the tail (unscored or beyond the head) follows in fused
order; cut at `k`. Fused rank is the position in the candidate list, which `fused_terms`
already tie-broke by ascending `DocId` (`fusion.rs:35–40`), so the rule stays deterministic
(Principle VI).

## D2 — The oracle for the rule: the 006 reference generator, extended

`reference/gen_006_fixtures.py` has `order_reranked` and `ORDER_CASES` and writes
`reference/fixtures/006/pipeline_order.json` (`{"cases": [...]}`), checked by
`crates/xtriever-pipeline/tests/rerank_golden.rs`. **Decision**: add `order_interpolated(fused,
fused_scores, scores, d, k, alpha)` and `INTERPOLATE_CASES` (both present; empty title-like
single candidate; constant cross-encoder column; constant fused column; ties broken by fused
rank; head shorter than the depth; k below the head; α 0 and 1) to the generator, writing a
second key `interpolate_cases` — the existing `cases` array is regenerated byte-identical
(checked with `git diff`). The Rust golden test gains `every_interpolation_case_is_exact`.
The end-to-end oracle is 014: `hybrid-rerank-v3` must equal `specs/014-rerank-depth-study/runs/lin-0.5-d20.<d>.json` per query to 1e-6 (SC-001) and, where
`target/xt-rerank-study/<d>/lin-0.5-d20.jsonl` still exists locally, list for list.

## D3 — The descriptor and existing indexes (Q1 = A)

`Descriptor` (`src/descriptor.rs:14–26`, `format_version: 2`, key order = on-disk order) gains
`rerank_mode: RerankMode` after `rerank_depth`, `#[serde(default)]` = `Interpolate { alpha:
0.5 }`, serialized as `{"interpolate": {"alpha": 0.5}}` / `"replace"` (serde's
`rename_all = "snake_case"` externally tagged enum). A descriptor without the key (every
index built before this feature, including the shipped Wikipedia index and the 007 fixture
index) reads as the default; `FORMAT_VERSION` stays 2 — the descriptor's own test asserts the
version and passes. `check_identity` does not compare the mode (it is a search rule, not an
identity of the indexed data). **ADR-0012** records: the default behaviour change, the new
key, the missing-key semantics, and the reproducibility path (the per-search override).

## D4 — Configuration, options, validation

`HybridConfig` (`src/types.rs:25–42`) gains `rerank_mode: RerankMode` (default
`Interpolate { alpha: 0.5 }` in `new`); `validate` (`src/index.rs:76–…`) rejects an α outside
`[0, 1]` or non-finite with `Error::Schema("rerank alpha must be within [0, 1]")`.
`SearchOptions` (`src/types.rs:66–80`) gains `rerank_mode: Option<RerankMode>` (`None` = the
index's mode); `search` validates an override's α the same way with `Error::Schema` as well (the
variant `HybridIndex` already uses for configuration input; `xtriever_core::Error` gains
nothing — no core change). The effective mode is resolved beside the effective depth (`search.rs:167–172`).

## D5 — Explain and features

`HitExplain` (`src/types.rs:128–143`) gains `rerank_combined: Option<f64>` (the ordering score
under `Interpolate`; `None` under `Replace` or when unscored); `features()` grows from 7 to 8
with the pipeline constant `RERANK_COMBINED = "rerank.combined"` beside `RERANK_RANK` (no
`xtriever_core::features` change). `Response::hits`' doc comment states both orders. The
FFI `HitExplain` record mirrors the field; the Swift parity test's feature-name list and the
Python test's gain `"rerank.combined"` (they assert the exact list).

## D6 — The FFI and Python surfaces

uniffi 0.32.1's `#[uniffi(default = …)]` accepts literals, `None`, `Some(…)`, `[]` and the
bare `default` (`uniffi_macros-0.32.1/src/default.rs:17–66`); the bare form renders `Type()`
for enums in Python (`uniffi_bindgen-0.32.1/src/bindings/python/pipeline/default.rs:24–48`),
which is not a constructible value for an enum with a data-carrying variant, and a path
literal such as `RerankMode::Replace` is not parseable there. **Decision**: the wire type is
`#[derive(uniffi::Enum)] RerankMode { Replace, Interpolate { alpha: f64 } }`; `IndexConfig`
and `SearchOptions` carry `rerank_mode: Option<RerankMode>` with `#[uniffi(default = None)]`
(the crate's existing idiom for `rerank_depth`, `types.rs:17`) — `None` = the engine's
default at build, the index's mode at search; `IndexInfo` carries `rerank_mode: RerankMode`.
The Python package re-exports the enum; `python/README.md` documents the default and the
override. The generated Swift is git-ignored (built by `scripts/build-ios-package.sh`), so
only the hand-written tests change: `InfoTests` asserts `rerankMode`, `ParityTests`' feature
list gains the eighth name.

## D7 — Goldens: regenerate with the existing generator

`crates/xtriever-ffi/examples/fixture_index.rs` builds the fixture index from
`reference/fixtures/005/hybrid.json`, searches eight queries with and without the re-ranker
at depth 5 and writes `swift/Xtriever/Tests/Fixtures/expected.json` (`info` + `queries`, score
bits). **Decision**: run it once after the change; `info` gains `rerank_mode`; only the
`with_reranker` responses' heads may differ (`without_reranker` must be byte-identical — a
check in the gate, and the diff summary goes to the report, spec SC-003). Python's suite reads
the same file (`python/tests/conftest.py:22`). The Swift suite runs on the simulator locally
(the owner's obligation as in 010; the simulator id only on the command line).

## D8 — The harness: `hybrid-rerank-v3`

`xtriever-eval` is `std`-only and cannot name the pipeline's type: `RerankConfig` gains
`mode: RerankMode` with the eval crate's own `enum RerankMode { Replace, Interpolate { alpha:
f64 } }` (serde, in reports — the same shape as the descriptor's, so a report says which rule
produced it); `hybrid_rerank_v1` / `v2` set `Replace` (their baselines reproduce);
`hybrid_rerank_v3()` = `hybrid_baseline_v2` re-ranked at depth 20 under `Interpolate { 0.5 }`.
`examples/beir.rs` maps the eval mode to the pipeline's in `SearchOptions` (an override per
search, so the example needs no descriptor change), dispatches the name, and `--rerank-depth`
keeps working. Baselines under `specs/015-rerank-interpolation/baselines/`, verified by the
003 scorer and compared per query with 014's cells (a `beir compare`-style check is not
enough — the cells carry `per_query`; `reference/rerank_study.py` gains `check-cell` — per-query
metrics to 1e-6, lists exact when the derived run is given — and `golden-diff` for the
007 regeneration summary).

## D10 — Costs and not done

No new model calls; the normalisation is arithmetic over ≤ 20 numbers per query — no bench
claim beyond "unchanged calls" (spec SC-005); the three `hybrid-rerank-v3` runs ≈ 50 min
(depth 20, as 013). No Wikipedia rebuild, no device record (Q1 = A; memory and latency
unchanged in kind), no per-dataset α, no conditional re-ranking, no LTR feature retraining
(the LTR stage is not yet trained on these features).
