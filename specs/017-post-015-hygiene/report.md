## 2. The budget test (spec US2)

Before: `a_short_time_budget_yields_a_partial_rerank_without_an_error` asserted `elapsed_ms <
1000` under a fixed 200 ms budget and failed on this laptop **on `main`** (`q0: 3414 ms`
today, `q0: 3233 ms` in 015).

It took three rewrites to get a test that is about the contract and not the machine, and
each step is worth recording:

1. *Fixed budgets 200 → 10 ms, no elapsed bound.* Still failed here alone: on a slow machine
   no fixed budget reaches the re-ranker at all (every stage report said `skipped`), while a
   fast machine finishes everything inside 200 ms. A fixed budget is machine-dependent in both
   directions.
2. *Budgets derived per query from its own measured cost* (depth-0 time + a fraction of the
   re-rank time). Passed alone; failed inside the full model-backed suite (22 tests in
   parallel, 15 minutes for this one) — under that load the cost measured a moment earlier
   no longer predicts the next call.
3. *Bisection per query between "too small" (skipped / nothing scored) and "too large"
   (fully re-ranked), re-measured at every step*, and — the last number to go — the "generous"
   60 s budget of the negative half was itself exhausted under the contended suite. The
   negative now uses **no budget at all**.

Final form: for each fixture query, an unbudgeted depth-0 search and an unbudgeted full
search give the bisection's bounds and the negative half (no budget → nothing skipped, every
candidate re-ranked); then up to eight bisected budgets, each asserting `Ok` in degrading
mode, `!time_limit_ignored`, scored hits first, until one query is partially re-ranked. **No
assertion mentions wall-clock time.** PASS alone (≈ 5 min) and inside the contended suite
(22/22, 1,689 s). Mutation check: with the re-ranker's remaining budget handed as `None`
(`search.rs` `max_time: remaining` → `None`), the test fails on "no query was partially
re-ranked" — restored, `git diff --stat main -- crates/xtriever-pipeline` empty.
